### 客户端 "connection error" 排查（结论：网关侧无问题）
用户报：base=`http://localhost:7863/chat2/v1`、model=`default` → connection error。排查事实：
- 网关侧全通（走 localhost 实测）：`POST /chat2/v1/chat/completions` `{"model":"default"}` 非流式/流式均 **200**（流式 `text/event-stream` + SSE 正常），`GET /chat2/v1/models` **200**。
- **API 路由强制鉴权**：缺 `Authorization: Bearer <config.api_key>`（当前 `api_key=test_key`）→ 401；`httpauth.VerifyBearer` 只认 `Authorization: Bearer ` 这一种，前缀**大小写敏感**。
- **无 CORS**：OPTIONS 预检 404、响应无任何 `Access-Control-Allow-Origin` → 浏览器/Electron 网页内核客户端会被拦（本次用户是 CLI/SDK，已排除）。
- 无代理环境变量；`localhost` 解析到 `127.0.0.1`；**本机 IPv6 回环不可用**（`ping ::1` = General failure），`http://[::1]:7863` 必然连不上。
- 路径必须精确，以下都 404：`/chat2/v1/models/`（尾斜杠）、`/chat2/v1/v1/...`（多一层 v1）、`/chat2/v1/messages`（Anthropic 形态，网关只实现 OpenAI 形态）。
- 用户自测时踩的坑：**cmd.exe 不认单引号**，`curl -d '{"model":"default"...}'` 会把 `'` 原样发出去 → 上游 `11101 Unmarshal chat params failed: invalid character '\''`（网关把上游错误原样透传）。cmd 正确写法：外层双引号 + 内层 `\"` 转义，或 `--data-binary @body.json`（文件存 UTF-8 无 BOM，顺带避开 cmd 中文 GBK 乱码）。
- 遗留：用户实际报错的客户端/工具名与完整报错原文未知，尚未定位到具体客户端侧原因。
